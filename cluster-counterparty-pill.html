ATLS-367 scenarios

What this mock shows

  • When the AI named a vendor for rows that have no counterparty, the action row gets one more button: ✦ Set counterparty: DoorDash 92%. The % is the AI's confidence in the name and turns amber under 70%. Any score is shown; if the AI can only say something vague ("Bank", "Payment", "Transfer") it gives no suggestion and there's no button.
  • A row counts as empty when it has no counterparty (—), or when the AI set it to "Unknown". "Unknown" picked by a person or a rule is left alone.
  • Only For Review rows are filled. Posted, Flagged and Excluded rows are skipped. Only the counterparty changes; COA and type stay.
  • If the name is already a counterparty, the button opens a small confirm, where the name can also be changed. If it's new, it opens the existing Create counterparty drawer (name + type); "Create and apply to N" does both. If the name turns out to exist (active or switched off), the drawer says so after Create is clicked, as it does today, and offers to use or reactivate it. No duplicate is created.
  • Tick rows first to apply to just those rows. With nothing ticked, the button ticks every row in the cluster (Cancel unticks them).
  • Filled rows become manual (a person applied them). There is no Undo for now.
  • The ⋮ menu is unchanged. The button goes away once every empty row has a counterparty.
